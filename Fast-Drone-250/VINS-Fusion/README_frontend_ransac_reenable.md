## 一句话结论

重新打开前端几何外点剔除 `rejectWithF()`（RANSAC 基础矩阵），并**同时删除**其函数体内多余的
`reduceVector(cur_un_pts, status)`。此改动消除了"一动前端就必然飘飞"的确定性 bug；
全量 `RUNS=3` 回归中 7/8 的包三次全稳，但 `2026-06-29-16-19-34.bag` 仍存在偶发飘飞的尾部风险，
尚未彻底根治，**上线前需知晓此风险**。

## 改了哪条线

只改前端 `feature_tracker.cpp`，两处：

1. **第 439 行**：`//rejectWithF();` → `rejectWithF();`
   重新启用 RANSAC 几何一致性外点剔除（stock VINS-Fusion 默认即开启）。
2. **`rejectWithF()` 函数体（原 629 行）**：删除 `reduceVector(cur_un_pts, status)`。

## 为什么必须同时删掉那一行（根因）

这是本次修复的核心，不是可选项：

- 当前代码调用点在 **439 行**，而 `cur_un_pts` 的重算在 **494 行**（`undistortedPts(cur_pts)`）——在调用之后。
- 改动版的 `rejectWithF()` 函数体里比 stock 多了一行 `reduceVector(cur_un_pts, status)`。
- RANSAC 一旦打开，运行到 439 行时 `cur_un_pts` 还是**上一帧的旧值**，尺寸与本帧
  `status`（按当前 `cur_pts` 尺寸生成）不一致。`reduceVector` 按 `v.size()` 遍历却用
  `status[i]` 索引 → 越界读 + 向量错位 → 送后端的去畸变归一化坐标与 `ids/cur_pts` 错位
  → 表现为绿色 `imu_propagate` 一动前端就飘飞。
- stock 之所以没问题：它在 `rejectWithF()` 里**不 reduce** `cur_un_pts`，而是等 494 行统一重算。

删除该行后，`cur_un_pts` 永远由剔除后的 `cur_pts` 现算，不可能错位，与 stock 行为一致。
